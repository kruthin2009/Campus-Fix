# CampusFix V1.11.0 — Phase 1 Student Experience

## Implemented in this source update
- Added an advisory duplicate-complaint warning during student submission. It checks the same student, tower, room, and department, and compares meaningful words in title/description. It never blocks a legitimate complaint; the student can continue.
- Added student reopening requests for complaints in `closed` or `rejected` status.
- Added administrator review controls on the complaint detail page to approve/reopen or decline a pending request.
- Added Firestore rules for `reports/{reportId}/reopenRequests/{requestId}`: students can create requests only for their own reports; administrators can review them.
- Reuses existing real-time complaint detail/timeline subscriptions and in-app notification centre.
- Existing worker completion and admin closure flows already create student notifications; retained those flows.

## Not included / requires separate setup
- Browser push notifications (FCM): requires Firebase Cloud Messaging web configuration, a VAPID key, service-worker integration, and testing on the target hosting domain.
- Duplicate detection is a lightweight heuristic, not an AI/ML model.
- Notification creation remains best-effort in the existing service; reliable delivery guarantees require server-side Cloud Functions or another trusted backend trigger.

## Deployment checklist
1. Run `npm ci`.
2. Run `npm run build`.
3. Review and deploy `firestore.rules` to Firebase only after reviewing the project environment.
4. Test as a student: submit a complaint, confirm duplicate warning, request reopening of a closed/rejected complaint.
5. Test as an administrator: open the same complaint, approve or decline the reopening request.
6. Verify the student receives the in-app decision notification.
7. Test existing worker completion and admin closure notifications.
8. Do not label the phase production-complete until the above tests pass in the connected Firebase project.
