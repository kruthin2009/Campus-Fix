# CampusFix V2.0.6 deployment notes

## Photo storage
- Student complaint photo: Firebase Storage path `reports/{studentUid}/{timestamp}-{filename}`.
- Worker completion photo: Firebase Storage path `reports/{reportId}/completion-{timestamp}-{filename}`.
- Supported: JPEG, PNG, WebP; original file maximum 5 MB. Browser optimization resizes large photos and converts to WebP when supported and smaller.
- Selected photos are no longer silently dropped: upload failure is surfaced to the user.
- Confirm Firebase Storage is enabled and `VITE_FIREBASE_STORAGE_BUCKET` points to the intended bucket. Deploy `storage.rules` and test with student, assigned worker, team worker and unrelated worker accounts.

## Worker workspace
- Worker navigation now includes My Work, Announcements & Maintenance, and Latest AI News.
- Admin announcement audience options: everyone, students only, workers only.
- Workers see announcements addressed to everyone/workers and active maintenance schedules assigned to them or unassigned to a team.

## Latest AI news
- `/api/ai-news` fetches Google News RSS headlines and caches responses at the Vercel edge for 15 minutes (stale while revalidating for up to one hour).
- Headlines link to original publishers. The feed is informational and external; CampusFix does not independently verify publisher claims.
- If the external feed is unavailable, the worker portal continues to work and displays an unavailable state.

## Validation and deployment
Run from the project root:
```powershell
npm ci
npm run check:release
npm run check:links
npm run build
```
Then deploy Firebase rules only after reviewing the target project:
```powershell
firebase use
firebase deploy --only firestore:rules,storage
```
Test uploads and audience visibility with separate role accounts before merging to the production branch. Vercel deployment and AI-news endpoint availability require a successful production deployment.


## V2.0.7 runtime reliability notes
- The service worker must not cache `/api/*`; these endpoints are network-only. It now uses a new cache namespace and network-first document navigation so a deployed app shell cannot keep pointing to stale bundles.
- AI and news clients validate response text before JSON parsing. If Vercel returns an HTML fallback, an empty body or a non-JSON error, the UI displays an actionable message rather than an uncaught JSON parser exception.
- Required Vercel environment variables for AI classification: `OPENAI` + `_API_KEY`, `OPENAI_MODEL` (optional; defaults to `gpt-4o-mini`), and either `FIREBASE_WEB_API_KEY` or the public `VITE_FIREBASE_API_KEY`; also `FIREBASE_PROJECT_ID` is needed for admin-only AI assignment recommendations. Set them for the Production environment and redeploy after saving. Never use `VITE_` for the OpenAI key.
- The AI and AI-news endpoints are Vercel serverless functions in the root `/api` directory. Confirm `/api/ai-news` returns JSON and `/api/ai` responds with HTTP 405 to a browser GET (it accepts authenticated POST only). A Vite local dev server alone does not automatically emulate Vercel functions.
- After deploying, perform one hard refresh or clear the old site data once to discard any already-open stale application bundle. The updated service worker will then manage future updates without caching API responses.
