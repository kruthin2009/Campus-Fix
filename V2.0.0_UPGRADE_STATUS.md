# CampusFix V2.0.0 — Upgrade status and implementation boundaries

## Included in this package
- Refined public landing-page palette with softer slate/navy surfaces, muted green/teal accents, calmer card borders and reduced hover movement.
- Updated visible public version label and package metadata to V2.0.0.
- Retained the existing CF branding/PWA assets and the existing application routes and Firebase integration.
- Retained the existing complaint timeline, role-based portals, duplicate-similarity helper, rule-based complaint categorization, basic tower/category trend summaries, and in-app notification service.
- Existing worker completion flow already writes a `report_completed` notification to the submitting student; existing close flow writes a `report_closed` notification. These are in-app Firestore notifications, not guaranteed browser push notifications.

## Existing code capabilities that should be verified in a live test
- Complaint submission and student tracking.
- Admin assignment and worker task views.
- Worker progress and completion, including optional resolution photo.
- Student in-app notification when work is marked completed and when a complaint is closed.
- Existing Firestore role/ownership rules.

## Not delivered as completed features in this package
The following require additional UI, server-side enforcement, data-model decisions, and end-to-end testing. They are a V2.x roadmap, not completed functionality:
- Browser/mobile push notifications and delivery receipts.
- Student-requested reopen workflow with admin approval.
- Full duplicate complaint prevention workflow in the submission UI.
- Worker task checklists and mandatory before/after proof policy.
- Full SLA timers, escalation automation, and scheduled jobs.
- Complete immutable audit logging across all administrative and worker actions.
- Interactive campus floor/tower map and hotspot visualization.
- Workload/availability-aware automatic worker assignment.
- Trained ML predictive-maintenance model. Existing trend helpers are descriptive summaries, not a trained prediction model.
- AI chatbot and model-backed natural-language categorization. Existing categorization is keyword/rule based.
- Automated backup/export workflows and notification delivery tracking.

## Required verification before production deployment
1. Run `npm ci` and `npm run build` in a clean environment.
2. Test each role with separate student, worker, and administrator accounts.
3. Submit a complaint, assign it, start work, mark it completed, and verify the student's in-app notification.
4. Close the complaint and verify the student receives the closure notification.
5. Verify Firestore and Storage rules in the Firebase emulator or a non-production test project before deploying any rules changes.
6. Test the PWA update and icon refresh on Android and iOS after deployment.

Do not describe roadmap items as implemented or claim AI prediction, push delivery, or SLA automation until those are built and tested.
