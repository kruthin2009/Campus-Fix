# CampusFix V1.14.0 — Phase 4: AI Integration

## Implemented in this package
- Added a Vercel serverless AI endpoint at `api/ai.ts` using OpenAI Chat Completions.
- The endpoint verifies Firebase ID tokens through Firebase Authentication before processing requests.
- Added server-side environment configuration; the OpenAI secret is never included in browser code.
- Student complaint form can request an AI department/category and priority recommendation, review the reason/confidence, and explicitly apply it.
- Admin Smart Center can request AI complaint classification and priority recommendations.
- Admin Smart Center can request a worker-team recommendation based on department match and current active assigned workload. It does not make the assignment.
- Added a CampusFix workflow assistant. It receives only general workflow context and does not access private complaint records.
- Existing local duplicate matching remains available and is explicitly labelled as rule-based text similarity, not AI.
- AI suggestions are optional and do not automatically submit complaints, change priority, or assign teams.

## Required deployment configuration
Set these in Vercel Project Settings → Environment Variables:
- `OPENAI` + `_API_KEY` — secret OpenAI API key (server-side only)
- `OPENAI_MODEL` — optional; defaults to `gpt-4o-mini`
- `FIREBASE_WEB_API_KEY` — Firebase project's Web API key (same value as `VITE_FIREBASE_API_KEY`)

Redeploy after adding variables. The `/api/ai` endpoint is available only when deployed to Vercel or another compatible serverless host. A static local Vite preview will not execute this API route.

## Not included / limitations
- No AI embeddings or semantic vector database for cross-student duplicate detection.
- No automatic worker assignment.
- No access to live private reports from the assistant.
- No AI-generated maintenance predictions; predictive metrics remain descriptive summaries of existing reports.
- AI calls require an OpenAI account/API key and may incur usage charges.
- Firebase ID token verification confirms the account is signed in; role-based admin authorization for the admin-only AI actions is not enforced by this endpoint. Do not treat this endpoint as a privileged data API. The current actions are recommendation-only and the endpoint accepts no Firestore writes.
- Add production rate limiting/usage quotas before broad public rollout.

## Verification
Source-level secret scan and production build status must be recorded after running the commands locally. This package is not marked build-verified until `npm ci` and `npm run build` pass on the recipient's machine.


## Security hardening update
- Firebase ID tokens are verified before every AI request.
- Worker-team recommendations now independently verify the caller's Firestore profile and require an administrative role on the server.
- AI responses are validated against the supplied department/team list and allowed priority values before being returned to the client.
- Added per-instance request throttling and a 25-second provider timeout. The throttle is best-effort per serverless instance; production-wide rate limiting requires a shared store.
- Added `FIREBASE_PROJECT_ID` as a server-side environment variable for role verification.
